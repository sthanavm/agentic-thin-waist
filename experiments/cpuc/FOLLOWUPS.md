# Follow-ups — written down, not done

Work this study found and deliberately did not do, with enough detail that
someone else can pick it up. Each entry says why it was left.

## Collapse the two application registries into one

**Status:** not started. Deliberately out of scope of the correction PR that
found it.

**What is wrong.** There are two registries of the same thing, and which one
decides a run depends on the code path:

| registry | reached by | drives |
|---|---|---|
| `shared/apps.py` `default_url` | `shared.apps.url_for` → `pramana_helpers.build_collector_jobs` | **every run with a player**, i.e. every QoE row, including all of CPUC |
| `pramana_helpers.APP_REGISTRY[app]["url"]` | `ExperimentConfig.url_for` → `_build_workflow` | the NetGent workflow and the `wget` shell apps |

`shared/apps.py` described itself as the single source of truth, which it was
not. Both carry a URL for `youtube`, `vimeo`, `twitch` and `tubi`.

**What it has already cost.** Twice, that we know of:

- **Twitch.** The channel was repinned to `lofigirl` in `APP_REGISTRY` with a
  comment saying it was pinned, while the collector still opened `relaxbeats`
  — which tops out at 720p, so the sweep would have aborted at the source gate
  with the comment insisting it could not.
- **Tubi.** The two registries named **different films**
  (`568500/forrest-gump` and `593796/another-cinderella-story`), so which movie
  a run measured depended on which path drove it. No Tubi run was ever
  collected, so no result is affected — this one was caught before it cost
  anything, which is luck, not design.

**What holds the line meanwhile.** The docstrings now say which registry drives
which path, and
`experiments/cpuc/tests/test_harness.py::test_no_undeclared_url_divergence_between_the_two_registries`
fails on any undeclared divergence. Two remain declared, both harmless and
both unresolved: `youtube` and `vimeo` differ only by a mute/muted flag.

**The fix, when someone takes it.** Make `APP_REGISTRY` derive its `url` from
`shared.apps`, not duplicate it:

1. In `pramana_helpers`, drop the `"url"` key from `APP_REGISTRY` and have
   `ExperimentConfig.url_for` fall back to `apps_registry.url_for(app)` after
   `cfg.app_urls`. `apps_registry` is already imported at the top of the file.
2. Keep `domains`, `type`, `plot_directions` and `color` in `APP_REGISTRY` —
   those are read on every path and are not duplicated anywhere.
3. Reconcile the two mute-flag divergences first, deciding each on purpose:
   muting changes whether an audio track is decoded, which changes demand.
4. Then delete `KNOWN_URL_DIVERGENCES` from the test and keep the test, so the
   invariant becomes "the two always agree" with nothing to declare.

**Why not now.** `shared/` is shared with branches in flight (PR #22 is built
on our Meet branch), and re-plumbing `APP_REGISTRY` inside a correction PR
would both enlarge a large PR and put a behaviour change where reviewers are
looking at data claims. The minimal fix — honest docstrings plus an enforcing
test — removes the silence without touching the plumbing.

## Re-run Meet below 1 Mb/s with a collector that survives

**Status:** blocked on the collector, not on analysis.

Three Meet points (1 Mb/s @ 50 ms, 0.5 Mb/s @ 20 and 50 ms) carried remote
video the collector never sampled, so their quality is unmeasured. The
captures prove video arrived; they cannot show what it looked like. See the
Meet section of `RESULTS.md`. Nothing in the archive can answer it — it needs
those three points re-run.

## `sweep.py` cannot reproduce its own three-latency data

**Status:** known gap, not fixed.

The committed `sweep.py` has no `--rtt` flag, so the 50 ms and 100 ms rows in
`streaming_cpuc_runs.csv` cannot be regenerated by running it. The conditions
themselves are parameterised (`C.sweep_plan(reps, rtt_ms=...)` and
`C.sweep_conditions(rtt_ms=...)`), so this is a missing argument rather than a
missing capability: `sweep.py` takes `--reps`, `--out-root`, `--csv` and
`--marker`, and never passes `rtt_ms`. Until it is
added, those rows are reproducible only from the archived run directories.
